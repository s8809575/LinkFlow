# 模块D 设计说明

## 1. 概述

模块D（PC 业务能力面）是 LinkFlow 项目中负责**控制指令执行、屏幕截图、剪贴板双向同步、文件上传、审计日志**的服务端模块，通过 JSON-RPC over TCP（端口 8089）向已配对的客户端暴露能力。

## 4. 主要接口

### 4.1 file.upload_init

```
请求: {"method": "file.upload_init", "params": {"path": "C:/dest.bin", "total_chunks": 3}}
响应: {"result": {"upload_id": "<uuid>"}}
错误: -32013 PATH_REQUIRED / -32018 INVALID_TOTAL_CHUNKS / -32018 PATH_NOT_ALLOWED
```

### 4.2 file.upload_chunk

```
请求: {"method": "file.upload_chunk", "params": {"upload_id": "...", "chunk_index": 0, "data_b64": "<base64>"}}
响应: {"result": {"ok": true, "chunk_index": 0}}
错误: -32013 UPLOAD_ID_REQUIRED / -32014 INVALID_DATA / -32015 CHUNK_RECEIVE_FAIL
```

### 4.3 file.upload_commit

```
请求: {"method": "file.upload_commit", "params": {"upload_id": "..."}}
响应: {"result": {"ok": true, "path": "C:/dest.bin", "crc32": 12345, "size": 1024}}
错误: -32016 SESSION_NOT_FOUND / -32016 CHUNKS_MISSING / -32016 COMMIT_FAIL
```

### 4.4 clipboard.get

```
请求: {"method": "clipboard.get", "params": {}}
响应: {"result": {"text": "剪贴板内容"}}
```

### 4.5 screen.snapshot


## 5. 与其他模块的集成

### 5.1 整体架构

```
客户端（手机/Android）
    │
    ▼
LinkFlowRpcServer (TCP:8089) ◄──── Module-B（RPC Session）
    │
    ├── system.control ────────→ MonitorService.execute_control_command()
    ├── screen.snapshot ──────→ MonitorService.get_screen_snapshot()
    ├── clipboard.get ────────→ ClipboardService.get_clipboard_text()
    ├── clipboard.set ────────→ ClipboardService.set_clipboard_text()
    ├── file.upload_* ─────────→ UploadService.*
    └── audit.query ───────────→ AuditService.query()
```

### 5.2 模块间依赖

| 依赖方向 | 说明 |
|----------|------|
| Module-A → Module-D | 提供 `PairingContextDTO`（pairing_id + key），用于 `pair.bind` 校验 |
| Module-B → Module-D | 安全通道建立后，所有 RPC 请求由 Module-D 处理 |
| Module-C → Module-D | 文件上传功能被 Module-D 的 `file.upload_*` 使用 |

### 5.3 冻结 DTO（IDL-v1.0.0）

模块D使用的 DTO 与冻结版本一致，无新增字段：

```json
// clipboard.get 返回
{"text": "string"}

// screen.snapshot 返回
{"data_b64": "string", "timestamp": 0, "width": 0, "height": 0}

// file.upload_init 参数
{"path": "string", "total_chunks": 0}

// audit.query 参数
{"start_ts": 0, "end_ts": 0, "limit": 100}
```

## 6. 关键设计决策

### 6.1 路径安全

`file.upload_init` 强制校验目标路径是否在 `LINKFLOW_ALLOWED_ROOTS` 环境变量指定的目录内，防止路径穿越。

### 6.2 防回环

剪贴板写入时设置 `_set_by_us_content` 标记，监听回调检测到相同内容时跳过不上报，避免 PC 向手机推送自己写入的内容。

### 6.3 Upload 原子性

`commit_session` 先完成文件合并、返回结果后，再清理 session 和临时文件。失败时 session 保留，可重试。

### 6.4 审计日志轮转

日志文件超过 10MB 时自动轮转为 `.old`，防止无限追加。

### 6.5 Session 过期

每个上传 session 带有 `created_at`，每小时清理超过 1 小时未提交的过期 session，防止内存泄漏。

## 7. 配置项

| 环境变量 | 说明 | 默认值 |
|----------|------|--------|
| `LINKFLOW_ALLOWED_ROOTS` | 允许访问的根目录，多个用 `;` 分隔 | 无（不限制） |
| `LINKFLOW_PAIRING_ID` | 预设配对 ID | 自动生成 UUID |
| `LINKFLOW_PAIRING_KEY_B64` | 预设配对密钥（base64） | 自动生成随机密钥 |
